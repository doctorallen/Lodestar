# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Lodestar is a top-down pixel-art game for the phone browser (upright, or sideways with `#app.wide`) in plain JavaScript: no build step, no dependencies, no modules. A seed-star stands at the middle of one dark world; the Kindler, who is part of it, carries its light out in veins and fights what lives in the dark. Read `README.md` for the file map and controls, `js/tuning.js` for every number, `DESIGN.md` for the design (the Veins), and `DECISIONS.md` before changing a design decision. Log any new major gameplay decision there. Sections of `DESIGN.md` marked **(proposed)** aren't built yet; ask before building on them in a way that's hard to undo.

## Commands

```sh
python3 -m http.server 8000     # play at http://localhost:8000 (or open index.html)
npm ci                          # test tools only
npm test                        # everything CI runs
node test/gen.js --update       # re-record golden hashes after an intended generation change
node test/traces.js --record    # re-record the walking traces after an intended change to how bodies move
git config core.hooksPath .githooks
```

## Architecture

- **Globals and load order.** Every file is a classic script in one global scope, loaded in order by `index.html` (`util.js` first, `main.js` last). A new file needs its `<script>` tag. `test/check.sh` fails on duplicate top-level names, so give helpers distinctive names.
- **Installable, never stale.** `manifest.webmanifest`, `icons/` (drawn from the star by `test/icons.js`) and `sw.js` make it an installable web app. `sw.js` imports Tycho's worker (`vendor/tycho/dist/tycho-sw.js`, from Tycho, the shared engine, a git submodule at `vendor/tycho`), which goes to the network first for everything (revalidating past the HTTP cache) and uses its cache only offline; it caches what `index.html` names, so a new file needs nothing there. Don't make it cache-first. The deploy stamps `__BUILD__` in `sw.js` with the commit, so every deploy is a new worker, and writes `version.json` with `BUILD_INFO`. `js/pwa.js` runs Tycho's installable app (`Tycho.pwa`), which looks for a new worker whenever the game comes back to the foreground and every 15 minutes; when one takes over and the page isn't that build, it loads at once if a reload would lose nothing (`Pwa.loss`: motes carried, the thread), and otherwise asks, now or later (`screen-update`). `test/pwa.js` drives this over http.
- **Seeded generation.** The world is one floor from `generateFloor` (`game.js generateWorld`), built with `Rng(hashInts(seed, …))`, never `Math.random`, so it can be rebuilt and the golden hashes stay stable; the save keeps the seed and what's been done. Enemy placement uses its own seeded Rng. Combat rolls use `Game.dive.rng`. Cosmetic effects may use `Math.random` (`FX_R`).
- **The floor's space.** A floor's tiles and ore are a Tycho grid wrapping its own arrays (`f.grid`; `floorTile` is its lookup, the unbreakable edge outside), its rock is those tiles felt along the smooth wall line (`f.rock`, a `Tycho.collide.Tiles`: `rockAt`), and bodies ask its space (`f.space`: `bodyHits`, `bodyInRock`), all made by `floorSpace` (`floor.js`) as soon as the tiles are. Walking is `Tycho.move.topdown` (`moveBody`) and the steps on foot are `Tycho.path.distances` (`floorDistances`, which enemies follow); `vendor/tycho/docs/world.md` has them. `test/traces.js` replays walks recorded before they moved onto Tycho (and hashes the wall line, the body test and the flow field) and holds them bit for bit: re-record only for a change to how bodies move that's meant, and say so in the commit.
- **Time.** `Game.step(dt)` is one fixed 1/60 s step. The Kindler runs on real time; the world runs on `dt * Game.timeScale`.
- **One bar.** `d.p.hp` is the Kindler's light and his health (`game.js updateBar`): it drains in the dark, fills in the star's light (`star.js starLight`, `litAt`), and at nothing he falls and the star's core loses a piece. `d.pull` is derived from it for the renderers that dim the lamp. There is no charge: a cast costs only its cooldown.
- **Controls.** `js/input.js` is the game's names (`Input.move`, `isHeld`, `hand`, `consumeDash`/`consumeAct`, `block`, `Input.bot`) over Tycho's controls (`Tycho.input.Controls`, `vendor/tycho/docs/play.md`): the stick kept inside the left deck, with its flick to dash, the buttons, the keys, the hands' presses and releases, and new presses blocked while a screen is up. The map's drag, pinch and tap are Tycho's gestures (`Tycho.input.Gestures`); the wheel is the game's. Drawing the stick is the game's (`drawStick`).
- **Modals.** A screen sets `Game.modal`, which stops the simulation. Opening one calls `Input.block()` and `Input.guard()`, and its buttons ignore taps for 400 ms (`Input.guarded()`, `T.ui.tapGuard`). Screen buttons carry `data-act`/`data-arg`, run through `UI.acts`, and the screen redraws.
- **Rendering.** The world is simulated in world px (`TILE` = 16) but drawn in art px, `T.art.px` (1.5) to a world px, so a tile is 24 art px (`ATILE`); convert with `ap()` and round to whole art px, and never draw a sprite at a non-integer scale. Letter-row sprites are enlarged 1.5× before shading (`scale15Rows`), except those redrawn by hand at the art's size, which are marked `artNative(rows)`. The art is authored at `AP_ART` (1.5); with FINE GRAIN (the pause screen; `artFinePx`) `T.art.px` is 3 and `AF` (2) is the view's pixels to each authored one: what's painted from world sizes comes out finer of itself, the Kindler is rendered finer (`KD_F`), and every other sprite is enlarged by `AF` as it's finished (`artFine`), so sizes drawn straight to the view in art px are multiplied by `AF`. The `#view` canvas is one art px per canvas pixel, scaled up by whole device pixels, and the shorter side shows about `VIEW_MIN` (176) world px. Each frame has two layers, colour and emissive. Where there's WebGL2 the GPU draws the frame on Tycho's renderer (`vendor/tycho/docs/renderer.md`; `gpu.js` keeps the game's names over it, `docs/RENDERING.md`): `View.ctx`, `View.emCtx` and `View.overCtx` are a batcher's stand-ins for the 2D contexts (`GpuCtx`), so drawing code is written as for a 2D canvas and must keep to that subset; a canvas drawn from is copied to the atlas once, so a cached picture that's painted again needs `gpuDirty`; the floor's painted buffers go up as textures by the box `pntComposite` marks; and the rock in front of an actor is put back over it in the shader by `Gpu.feet`. The light is `lightScene` (ambient, plus each light source, in dithered bands, with emissive pixels at their own colour), as a shader over the scene's framebuffer (`gllight.js`) or in JavaScript without WebGL2; the two paths must agree: `test/gllight.js` draws the same frame both ways and holds them to a tone. Then the bloom, and the overlay unlit over it. `?perf` in the address draws a readout of the frame's cost on the overlay (`perf.js`). A buffer or texture the GPU may still be drawing from is never written (rings of buffers): a phone's tile-based GPU stalls on that. The world is one large floor (320 tiles square), and only a window of it is painted (`paint.js PWIN`, `T.paint.window`: 64 tiles square, 48 at FINE GRAIN): every whole-floor pixel buffer and GPU texture is window-sized, the painting code works in floor px throughout and indexes a buffer at `(y - PWIN.y) * PWIN.w + x - PWIN.x` (`OFF` in each function; a `pixBuf` carries its origin as `ox`, `oy`), and as the view nears the window's edge it moves (`pntWindowMove`: the overlap copied along, the exposed strip painted lazily in chunks round the view, `pntFrame`). Sprites carry anchors `ax`/`ay` at the feet.
- **The story.** `js/story.js` holds the story's lines (DESIGN.md, The story). Never say the turn outright: nothing before the ending may say that the Kindler goes into the star when the world lives, or that the sleepers come down to no one. Wick is dry and kind; lines are short enough to read on a phone. New first-time lines go in `WICK` and are said once with `Story.say(key)`.
- **Art style.** The game is in a painted style (`docs/PAINTED.md`, `js/paint.js`, `T.paint`): strokes of a few close tones, no outlines, rock rising from a steep three-quarter camera and hiding what stands behind it. `art.js` holds the palettes, the older sprites and tile painters. Only magitech glows. Rock tops are always darker than the floor, with lit rims and faces, so walls read as walls. Light numbers live in `T.light`.

## Testing changes

Drive the game headlessly with `puppeteer-core` through `test/lib.js` (`launch`, `openGame`); `openGame` waits for the loading screen (`js/loader.js`) and taps to begin, `intro: false` marks the opening seen, and `?noload` in the address skips the loading. Wait 450 ms after a screen opens before tapping. `Input.bot = { x, y, main, off, act }` drives the controls, and `UI.acts` runs any screen button. One-off scripts and screenshots go in `test/out/` (gitignored). Look at the screenshots for visual changes. Never edit `js/` while the smoke test runs: it loads the files live.

## Conventions

- Comments and in-game text are plain English. Match the surrounding density.
- Commits go to `main` with short sentence-case subjects. Every push to `main` deploys once the tests pass.
